# Markdown to Word (`.docx` / `.doc`) Converter Skill (WPS Office & MS Word Safe)

Converts any Markdown (`.md`) document into a styled Microsoft Word document branded for **Spider Express Logistics TMS** (`#0F3D62` Navy & `#1D4ED8` Blue palette, `Segoe UI` & `Consolas` Vietnamese-safe typography).

- **Primary Output Format (`.docx` — Default & Prioritized)**: Generated by [`md_to_docx_engine.py`](./scripts/md_to_docx_engine.py) (`python-docx`) starting from a genuine Microsoft Word `default.docx` template (`styles.xml`, `settings.xml`, `fontTable.xml`).
- **Secondary Output Format (`.doc` — On-Demand Fallback)**: WPS/Word-compatible MSO HTML `.doc` generated by [`md-to-docx.mjs`](./scripts/md-to-docx.mjs) when `--format=doc` or `--format=both` is passed.

## WPS Office & Microsoft Word Layout Safety Invariants

1. **Zero 1-Cell Percentage Layout Tables**: Never wrap banners, callouts, code blocks, or sign-off boxes in `<w:tbl>` with `w:type="pct"`. In WPS Office (Kingsoft Writer), percentage tables without explicit DXA `<w:gridCol>` collapse to `100` twips (`1.76mm` wide). Instead, all banners (`## H2`), question headings (`### H3`), callouts (`> ...`), code blocks, and sign-off boxes (`👉 Chốt...`) use **native OOXML Paragraph Shading (`<w:shd>`) and Paragraph Borders (`<w:pBdr>`)**, which automatically span 100% of the printable page width (`9866` twips / `17.4 cm`).
2. **Strict Fixed-DXA Data Tables**: Every Markdown table (`| col1 | col2 |`) sets explicit integer DXA widths (`<w:tblW w:w="9866" w:type="dxa"/>`, `<w:tblLayout w:type="fixed"/>`, proportional `<w:gridCol w:w="..."/>`, and `<w:tcW w:w="..." w:type="dxa"/>` on every cell).
3. **Zero Hanging-Indent Tab Jumps**: List items and checkboxes (`☑` / `☐`) use clean `left_indent` without `hanging` indent so WPS Office never inserts oversized tab gaps.
4. **Wrap-Safe Fill-in Dotted Lines**: Backticked continuous dots (`` `............` ``) are automatically converted into spaced dots (`. . . . . .`) inside a dashed `#F8FAFC` box so WPS Office wraps them cleanly within page margins.

## Steps

1. **Identify Source `.md` and Target Output Path**
   - Default to `.docx` in the same directory as the source `.md` file unless a custom output path is provided.
   - Done when `<input.md>` and target `<output.docx|.doc>` paths are resolved.

2. **Execute the Converter CLI**
   ```powershell
   npm run md:docx -- "<input.md>" "<output.docx>"
   ```
   Or directly:
   ```powershell
   node .agents/skills/md-to-docx/scripts/md-to-docx.mjs "<input.md>" "<output.docx>"
   ```
   Optional flags:
   - `--format docx|doc|both` (defaults to `docx`)
   - `--title "Custom Document Title"`
   - `--subtitle "Optional Subtitle"`
   - Done when the command exits with code `0` and prints `✅ [DOCX (WPS & MS Word Safe)] Generated: ...`.

3. **Verify Output File**
   - Confirm the generated `.docx` file exists and is `> 35 KB` (confirming full Word `styles.xml` and `settings.xml` inclusion).
   - Provide a clickable `file:///` link to the user.
